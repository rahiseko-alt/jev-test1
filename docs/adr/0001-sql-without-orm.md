# ORM を使わず、素のSQLで書く

`docs/design/05-stack.md` では当初 Drizzle ORM を使う予定にしていたが、土台を作る段階
（#3）で素のSQLに変更した。Drizzle は方言ごとに別の書き方で表を定義する必要があり、
SQLite と PostgreSQL の両方を既定に据える本アプリでは、結局2つの定義を二重に持つことに
なる。それなら、二重に持つものを「SQLの移行ファイル2本」だけに絞り、2つが同じ表と列を
持つことをテストで検査する方が、層が薄く読み解きやすいと判断した。

値は必ず差し込み（`?`）で渡す決まりにし、SQLの文字列に値を混ぜない。
PostgreSQL 側では `?` を `$1` の形に置き換えてから渡す。

将来、問い合わせが複雑になって型付きの組み立てが必要になったときは、この判断を
見直してよい。そのときは方言ごとの表定義の二重管理を受け入れることになる。
